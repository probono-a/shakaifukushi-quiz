# 実装計画: 解答の履歴に、選んだ選択肢を残す (Issue #19)

## 目的

今の履歴 (`history`) には正誤しかなく、間違えたときに、どの選択肢を選んだかが分からない。
選んだ選択肢を残せば、同じ取り違えをくり返していないかを、あとから分析できる。

## 使う人から見て変わること

- 解いている画面・結果画面・ダッシュボードは、何も変わらない
- 「学習履歴を CSV で出す」のファイルに、「選んだ選択肢」の列が増える
  - 例: `2` (1 つ選ぶ問題)、`1,3` (2 つ選ぶ問題)
  - これまでの履歴は、空欄のまま
- #14 (セッションの詳細) で見せるのは、#14 のときにやる。ここでは記録するところまで

## やること

### 1. DB (`db.py`)

- `history` に `selected_options TEXT` の列を足す
  - 新しく作る DB は `CREATE TABLE` に入れる
  - 今の DB は、ほかの列と同じく `PRAGMA table_info` で見て、無ければ `ALTER TABLE ... ADD COLUMN` で足す
- 値は、選んだ番号を小さい順にカンマでつないだ文字列 (`1,3`)
  - 正誤の判定 (`quiz.js` の `judgeAnswer`) で作っている文字列と同じ形
- これまでの行は `NULL` のまま (埋めようがないため)
  - `time_sec` の `NULL` と同じく、「記録していない」の意味

### 2. API (`routers/history.py`)

- `POST /api/history` の本文に `selected_options: list[int] | None = None` を足す
  - API では数の配列で受け、DB には小さい順にした `1,3` の形で入れる
  - 配列で受けるのは、`"1, 3"` や `"3,1"` のような形の揺れを API の入り口で防ぐため
  - 省略したとき・`null` のときは `NULL` を入れる (古い画面から送られても壊れない)
- `GET /api/history/export` の CSV の最後に「選んだ選択肢」の列を足す
  - `NULL` は空欄

### 3. クイズ画面 (`static/js/quiz.js`)

- `judgeAnswer` で `/api/history` に送る本文に、`selected_options: state.selected` を足す

### 4. CHANGELOG.md

- 「解答の履歴に、選んだ選択肢を残すようにした (CSV にも出る)」を足す

## テスト

### 自動テスト (`tests/`)

- `test_history_api.py` に足す
  - `selected_options: [3, 1]` を送ると、DB に `1,3` で入る
  - `selected_options` を省くと、DB に `NULL` で入る
  - CSV に「選んだ選択肢」の列があり、値が `1,3`・空欄で出る
- `test_db.py` に足す
  - `selected_options` の列が無い古い `history` に `init_db()` をかけると、列が足され、元の行は `NULL` のまま

### 手動で確かめること

テスト用の DB (`QUIZ_DB_PATH=data/quiz_test.db`) で起動して確かめる。

- 1 つ選ぶ問題と 2 つ選ぶ問題を解き、DB の `history` に `2`・`1,3` のように入る
- 間違えたときも、正解したときも入る
- CSV を出し、Excel で開いて「選んだ選択肢」の列が `1,3` のまま見える
  - ⚠️ Excel が `1,3` を数の `13` と読み違えないかを見る
  - 読み違えるなら、区切りを `1・3` などに変えるかを、そのときに相談する

## やらないこと

- 選んだ選択肢を画面に見せること (#14 でやる)
