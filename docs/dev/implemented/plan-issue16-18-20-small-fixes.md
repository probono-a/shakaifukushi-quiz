# 実装計画: 画面の小さな不具合を 3 つ直す (Issue #16・#18・#20)

## 目的

どれも小さく、同じ画面まわりの不具合なので、1 つのブランチ・1 つの PR でまとめて直す。

## 使う人から見て変わること

- #16: 編集画面で解説を「プレビュー」にしても、箇条書きの印が枠の外にはみ出さない
- #18: URL (`quiz.html?ids=...` など) から始めたとき、1 問目の出題の音が鳴らない
  - これまでは、最初の解答のときに、正解・不正解の音と一緒に遅れて鳴っていた
  - 2 問目からは、これまでどおり鳴る
- #20: URL から始めて 0 問だったときや、エラーのとき、設定の画面がふつうに使える
  - これまでは、科目の一覧が空で、モードのカードを押しても選べなかった

## やること

### 1. #16 プレビューの箇条書き (`static/css/style.css`)

- `.edit-md-preview` のところに、次の 1 行を足す
  - `.edit-md-preview ul, .edit-md-preview ol { padding-left: 1.4rem; margin: .3rem 0; }`
  - クイズ画面の解説 (`quiz.html` の `.fb-explanation ul, .fb-explanation ol`) と同じ値

### 2. #18 出題の音 (`static/js/sound.js`)

- `SoundManager` に「ユーザーがもう操作したか」の印を持たせる
  - 最初の `click`・`keydown` (キャプチャ) で立てる
- `play()` は、まだ操作していないときは、鳴らさずに何もしない
  - 今は、操作の前に呼ばれると、止められた音が次の操作のときに遅れて鳴る
  - 出題の音だけでなく、どの音でも同じにする。操作の前に鳴らせる音は無いため
- `quiz.js` の `renderQuestion()` は変えない

### 3. #20 設定の画面に戻るとき (`static/js/quiz.js`)

- `initSetup()` を、2 回目からは何もしないようにする
  - 先頭で印を見て、もう準備していれば戻る
  - イベントの登録が重なったり、回の選択肢が重複したりしないようにするため
- 0 問のとき・エラーのときに設定の画面に戻すところ (2 か所) を、1 つの関数 `backToSetup()` にまとめる
  - `state.config = {}` にする (#12 のとおり)
  - `await initSetup()` してから `showScreen('setup')` する
  - `initSetup()` 自体が失敗しても (サーバーが止まっているなど)、設定の画面は出す
- 設定の画面から始めて 0 問だったときは、今と変わらない (準備済みなので、選んだ設定がそのまま残る)

### 4. CHANGELOG.md

- 3 つの修正を足す

## テスト

### 自動テスト

- 3 つとも画面 (CSS・JS) だけの修正で、今の `tests/` (pytest、API と DB) では確かめられない
- 自動テストは足さず、今のテストがすべて通ることだけを確かめる

### 手動で確かめること

テスト用の DB (`QUIZ_DB_PATH=data/quiz_test.db`) で起動して確かめる。

- #16: 編集画面で、箇条書きのある解説をプレビューにし、印が枠の中に収まる
- #18: `quiz.html?ids=<2 問の ID>` で開き、1 問目で音が鳴らない。1 問目の解答で正解・不正解の音だけが鳴り、2 問目で出題の音が鳴る
- #18: ふつうに設定の画面から始めると、1 問目から出題の音が鳴る (今と変わらない)
- #20: `quiz.html?ids=no_such_id` で開き、0 問のお知らせのあと、設定の画面で科目の一覧が出て、モードを選んで始められる
- #20: 設定の画面から 0 問になる条件で始め、戻った画面で回の選択肢が重複していない
