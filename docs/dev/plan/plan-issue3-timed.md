# 実装計画: 解く時間を計るかどうかを、セッションの初めに選べるようにする (Issue #3・#12)

## 目的

じっくり解くときは、時間を計る意味がない。
計った値が入ると、ダッシュボードの平均の解答時間 (と、それを使う本番予想時間) がゆがむ。
そこで、セッションの初めに時間を計るかどうかを選べるようにし、計らないときは解答時間を記録しない。

あわせて、前のセッションの設定が残る不具合 (#12) を直す。
これが残っていると、2 回目のセッションで「時間を計る」のチェックが効かないため (下の「2. クイズ画面」)。
同じところで起きている、結果画面の「もう一度設定する」ボタンの不具合もまとめて直す。

## 使う人から見て変わること

### 今

- 解答時間は、どのセッションでも、知らないうちに 1 問ごとに計っている (画面には出ない)
  - 計るのは、問題が出てから解答するまで。解答のあとに解説を読む時間は入らない
- 計った時間は、ダッシュボードの 2 か所に出る
  - 「本番予想時間」のカード: 1 問あたりの平均 × 129 問
  - 科目別の正答率のグラフ: 科目ごとの平均を、オレンジの点で重ねている
- 調べものをしながら、じっくり考えて解いた問題も、同じように平均に入る
  - なので、平均が実際の試験のペースより長く出る

### これから

計るのは、「⏱️ 解く時間を計る」のチェックボックスがオンのときだけになる。

- チェックボックスは、「学習セッションを設定する」の画面 (ナビの「📝 クイズ」で開く画面) の、「学習を始める →」ボタンのすぐ上に出る
- オフで解いた問題は、本番予想時間・科目別の平均に入らない
  - 正答率・解いた数・学習の記録には、今までどおり入る
- 解いている画面は、何も変わらない (オンでもオフでも)

**チェックボックスの初期値と、操作による変わり方**

| 場面 | 操作 | チェックボックス |
| --- | --- | --- |
| 設定の画面から始める | 模擬受験のカードを押す | オンになる |
|  | ほかのモードのカードを押す | オフになる |
|  | カードを押したあと、チェックボックスを押す | 押すたびにオン・オフが切り替わる |
|  | 手で切り替えたあと、別のモードのカードを押す | そのモードの初期値に戻る |
| 設定の画面を通らずに始める | ダッシュボードのおすすめカード・苦手問題のボタン・問題 ID のリンク | 出ない。オフと同じ (計らない) |
|  | 問題を指定した URL (`quiz.html?ids=34_1,34_2,...`) | 出ない。オフと同じ (計らない) |
|  | URL の末尾に `&timed` を付ける | 出ない。オンと同じ (計る) |

**結果画面の「もう一度設定する」を押したとき**

クイズの画面 (`/quiz.html`) を開き直す。ナビの「📝 クイズ」を押したときと同じで、設定の画面のすべての項目が初期値に戻る。

| 設定の画面の項目 | 「もう一度設定する」のあと |
| --- | --- |
| 出題モード | ランダム |
| ⏱️ 解く時間を計る | オフ (ランダムの初期値) |
| 科目 | 全部外れる |
| 問題数 | 20 問 |
| 回 | 選んでいない |
| フィルター | 全部外れる |

- 前のセッションの設定は使われない。画面で選んだとおりに始まる
- 今は、問題数・回・フィルターが前のセッションの値のまま残る。これからは残らない
  - 前と同じ条件で解きたいときは、選び直す

**0 問で設定の画面に戻ったとき**

画面の項目は、選んだときのまま残る。そのまま、または選び直して「学習を始める →」を押すと、画面のとおりに始まる (#12 で直す)。

**これまでの記録**

- ⚠️ これまでに計った記録は、そのまま残る
  - 本番予想時間は、しばらくはこれまでの記録 (じっくり解いた分も入っている) で出る
  - 模擬受験を解くと、少しずつ本番のペースに近づく。これまでの記録が多いほど、近づくのはゆっくりになる
  - これまでの記録を外すことは、今回はやらない (下の「やらないこと」)

## 今回やること・やらないこと

やること:

- 「学習セッションを設定する」の画面に「時間を計る」のチェックを足す。初期値はモードで決める
- URL から始めるセッションは、`timed` があるときだけ計る
- 計らないときは、解答履歴の `time_sec` を `null` で送る
- セッションの `config` に、計ったかどうかを残す
- 「もう一度設定する」で、クイズの画面を開き直す
- 0 問・エラーで設定の画面に戻るときに、前のセッションの設定を空にする (#12)

やらないこと (必要になったら別 Issue にする):

- 解いている途中で、計る・計らないを切り替えること
- 選んだ値を次のセッションに引き継ぐこと (`localStorage` に覚えるなど)
- 画面に経過時間を出すこと (今も出していない)
- これまでの解答履歴の `time_sec` を直すこと
- 下の「見つけたが、今回は直さないこと」

## 決めたこと

- 初めから計るのは、模擬受験 (`edition`) のモードだけ
  - 本番のペースを知りたいのは模擬受験のときで、ほかのモードはじっくり解くことが多いため
- URL から始めるときは計らない。`timed` を付けたときだけ計る
  - 今は URL から模擬受験を始める入り口が無いので、困る場面は無い
- #12 の直しを、この PR に入れる
  - #3 のチェックが 2 回目以降も効くために必要で、直しは小さいため
- 「もう一度設定する」は、同じページで設定の画面を作り直すのをやめ、クイズの画面を開き直す
  - 作り直しが、下の 2 つの不具合と #12 の原因になっていたため
  - 開き直せば、初めて開いたときと同じ状態になり、仕組みがいちばん単純
  - 代わりに、問題数・回・フィルターも初期値に戻る。選び直しの手間は増えるが、分かりやすさを取る

## 一緒に直る不具合

計画を作るときにコードを読んで見つけた。どちらも「もう一度設定する」で設定の画面を作り直す (`initSetup()` を呼び直す) ことが原因で、開き直す形にすれば起きなくなる。

- クリックの処理が重なる
  - `initSetup()` は、呼ばれるたびに「学習を始める」ボタンとモードのカードに `addEventListener` で処理を足す
  - 2 回目以降は「学習を始める」1 回で `startSession()` が 2 回走り、セッションが 2 件作られるおそれがある (コードを読んでの推測。画面ではまだ試していない)
- 回の選択肢が足される
  - `initSetup()` が、呼ばれるたびに `/api/editions` の回を `edition-select` に足しているため、同じ回が 2 つずつ並ぶ (コードを読んでの推測)

## 見つけたが、今回は直さないこと

計画を作るときにコードを読んで見つけた。前からある不具合で、#3 とは別に Issue にする。

- URL から始めて 0 問だったとき、準備していない設定の画面に戻る
  - URL から始めるときは `initSetup()` を呼ばないので、モードのカードや科目の一覧が用意されていない

## 1. バックエンド

直すところは無い見込み。

- `POST /api/history` の `time_sec` は、もとから `float | None` で `null` を受け取れる ([routers/history.py](../../../routers/history.py))
- ダッシュボードの平均 (全体・科目別) は SQL の `AVG(time_sec)` なので、`null` の行は平均から外れる ([routers/stats.py](../../../routers/stats.py))
- セッションの `config` は `dict` をそのまま JSON で保存するので、`timed` を足しても API は変わらない ([routers/sessions.py](../../../routers/sessions.py))

## 2. クイズ画面

対象: [static/quiz.html](../../../static/quiz.html)、[static/js/quiz.js](../../../static/js/quiz.js)

### 「学習セッションを設定する」の画面 (`#screen-setup`)

- 「フィルター（任意）」の下、「学習を始める →」ボタンのすぐ上に、項目を 1 つ足す
  - 「⏱️ 解く時間を計る」のチェックボックス (`id="opt-timed"`)
  - 下に 1 行の説明: 「オンのときだけ、本番予想時間・科目別の平均に入ります」
- どのモードでも出す (`updateSetupOptions()` では隠さない)
- モードのカードを押したときに、チェックを付け直す
  - 模擬受験 (`edition`) ならオン、それ以外はオフ
  - 手で付け外ししたあとにモードを変えると、モードの初期値に戻る

### セッションの開始

- `config.timed` に、計るかどうか (`true` / `false`) を入れる
  - 設定の画面から: `startSession()` の `if (!Object.keys(config).length)` の中で、科目・件数と一緒にチェックボックスの値を読む
  - URL から: `DOMContentLoaded` で `state.config` を作るところ (`ids` と `mode` の 2 か所) で、`params.has('timed')` を入れる。値は見ない
- `config` はセッション作成の `POST /api/sessions` にそのまま送られるので、記録に残る

### 前の設定を空にする (#12)

- 今の動き
  - `startSession()` は、`state.config` が空のときだけ設定の画面を読む
  - 0 問で戻ったときも、「もう一度設定する」(`btn-retry`) でも、`state.config` は空に戻らない
  - なので 2 回目は、設定の画面で選び直しても、前のセッションの設定 (科目・件数・回・`timed`) がそのまま使われる
- 「もう一度設定する」: `btn-retry` の処理を `location.href = '/quiz.html'` にする
  - `initSetup()` の呼び直しをやめる。ページを開き直すので、`state` も画面もまっさらになる
- 0 問・エラーで戻るとき: `startSession()` の中で `showScreen('setup')` する 2 か所 (0 問のときと `catch`) で、先に `state.config = {}` にする
  - 画面の項目は選んだときのまま残し、次に「学習を始める →」を押したときに画面から読み直す
- #12 の案 (モードのカードを押したときに空にする) は使わない
  - 上の 2 つで、前の設定が残る経路がなくなるため
  - カードを押さずに「学習を始める →」を押したときも、画面のとおりに始まる

### 解答の記録

- `judgeAnswer()` で、`state.config.timed` が `true` のときだけ `time_sec` を送り、それ以外は `null` にする
- 問題の表示時刻 (`state.questionStartTime`) は、計らないときもそのまま取る (使わないだけ)

## 4. テスト

### 自動テスト

今回直すのはフロントだけで、JS のテストの仕組みは無い。
なので、`timed` の判定と #12 の直しは、下の手動の確認だけで押さえる。
自動テストでは、フロントが頼っているバックエンドの動きを押さえる (今の動きの回帰テスト)。

準備:

- `client` の fixture を、`tests/test_questions_api.py` から `tests/conftest.py` に移し、新しいテストでも使えるようにする
- 保存された値は、読む API が無いので、`db.get_db()` で DB を直接読んで確かめる
- `history` にはほかの表への外部キーが無いので、平均のテストでは、セッションや問題を作らずに `POST /api/history` だけで行を作る

`tests/test_history_api.py` (新規):

| テスト | 確かめること |
|---|---|
| `time_sec` が `null` | `POST /api/history` に `time_sec: null` を送ると、DB に `NULL` で保存される |
| 平均から外れる | `time_sec` が 10・20・`null` の 3 件で、`GET /api/stats` の平均が 15.0 になる (科目別も同じ) |
| すべて `null` | 平均が `null` になり、エラーにならない |
| `config` の `timed` | `POST /api/sessions` に `config: {"timed": false}` を送ると、DB の `config` にそのまま保存される |

### 画面の確認 (手動)

DB のコピー (`QUIZ_DB_PATH`) で起動して確かめる。

- AI: DB のコピーを用意し、サーバーを起動する。履歴・セッションの記録 (`time_sec`・`config`) を DB で確かめる
- ユーザー: ブラウザで画面を操作し、見た目を確かめる

確かめること:

- 「学習セッションを設定する」の画面
  - チェックが出る
  - 模擬受験を選ぶとオン、ほかのモードを選ぶとオフになる
  - 模擬受験 → ランダム → 模擬受験と切り替えると、オン → オフ → オンになる
  - 手で付け外ししてから始めると、その値で記録される
- オンで解く: 履歴に `time_sec` が入る。セッションの `config` に `"timed": true`
- オフで解く: 履歴の `time_sec` が `null`。セッションの `config` に `"timed": false`
- URL
  - `?ids=...`: `time_sec` が `null`
  - `?ids=...&timed`: `time_sec` が入る
  - `?mode=weak&timed`: `time_sec` が入る
  - おすすめカード・苦手問題のボタン: `time_sec` が `null`
- 「もう一度設定する」
  - 押すと、設定の画面のすべての項目が初期値 (上の表) になる
  - 模擬受験・チェックをオンで解き終え、「もう一度設定する」→ ランダムで始める: `time_sec` が `null`、`config` に `"timed": false`
  - URL から計らずに解き終え、「もう一度設定する」→ 模擬受験で始める: `time_sec` が入る
  - 2 回目以降も、「学習を始める →」1 回でセッションが 1 件だけ作られる
  - 2 回目以降も、回の選択肢が重複していない
- 0 問で戻ったとき (#12)
  - 科目を絞ったランダムで 0 問 → 模擬受験に切り替えて始める: 科目の絞り込みが効いていない
  - 0 問で戻ったあと、チェックボックスだけ切り替えて始める: 切り替えた値で記録される
- ダッシュボード: 本番予想時間・科目別の平均が、計った分だけで出る
- ダッシュボード (`time_sec` がすべて `null` の DB): 崩れずに出る
  - 「本番予想時間」のカードが隠れる
  - 科目別のグラフは、正答率の棒だけになる (オレンジの点・時間の軸・凡例が出ない)
  - DB のコピーで `UPDATE history SET time_sec = NULL` をしてから確かめる
